# 回声 · 桃花小院

## 产品意图

一个可以短暂停留的情绪小院。用户和小猫一起进入绿草、木屋和桃花围成的地方，点击右侧桃树的树洞，用写信的方式说心事，收到有温度、能说明参考来源的 AI 回信。木屋提供轻松的动物陪伴，留言板让来访者留下一天的温柔；养花以后再加入。

视觉参考是俯视像素农场的空间感：房屋保留木色与陶瓦色，草地保持绿色，粉色来自花树、落瓣与光照。场景及猫咪素材为本项目生成，没有提取参考游戏的地图、建筑、角色或商标。当前是一张完整场景图叠加热点，尚不是可行走的瓦片地图。

## 本版体验

1. 第一次进入，选择小猫毛色；可使用预设或自定义颜色。小猫以六帧跑步动画跟随电脑鼠标，停下后站立；电脑和触摸屏都能按住拖动。
2. 看小院、开关花瓣，直接点击树洞内部的“写一封信”，或把小猫拖进去。缩小屏幕时镜头偏向右侧桃树。
3. 打开米色信纸。可以选择先倾听或一起想办法；保留同意、停止、错误恢复和清空功能。
4. 用户自行开启生辰笺后才提供传统文化工具。出生时间未知时不补造时柱。
5. 回信按需要检索资料、提取练习、读取程序排盘。展示实际查阅的来源；它不意味着每一句回答都经过事实验证。
6. 关闭信纸回到小院。关闭页面或刷新清除聊天；猫咪颜色、动效偏好与养猫状态保存在本机，养猫状态不跟账号同步。
7. 点击左侧木屋的门，打开后进入暖木色小屋。小猫趴在中央，白手套触摸头、肚子、爪子、尾巴时分别蹭手、翻身、伸懒腰、轻摇；反馈都是积极的。顶部显示心情、饥饿、活跃，进入时有可收起的提示。
8. 每天北京时间 00:00 刷新一份猫粮，不累积。饥饿只有半饿/饱；心情每小时下降 4 点，活跃每小时下降 8 点，均限制在 0–100。抚摸增加 6 点心情，最快每 750 毫秒一次；实际在院子跑动才增加活跃。低于或等于 25 时分别出现想抱抱/想睡觉表情；两项都低时显示睡脸并同时说明两种状态。不会生病、死亡、离开，也没有付费粮或签到惩罚。
9. 木屋外留言板为木框中的可滚动白板。昵称/密码注册后可匿名或署名，自己的留言可收回。每天北京时间 00:00 清空全部留言，账号保留；主界面右下角的指南说明完整玩法。

养猫按服务端时间校准，以时间戳计算经过时间，无服务端游戏循环。当前状态在本机浏览器，能被本机用户改写或清除，属于轻量体验而非防作弊系统。后台不动画，关闭房间不绘制室内小猫。没有额外模型调用。

账号使用随机盐与 scrypt 散列密码，随机会话凭证仅存散列，Cookie 为 HttpOnly / SameSite=Strict，直接 HTTPS 连接时加 Secure；每次登录更新当前会话，七天过期。当前最多 1000 个账号；注册和登录按连接来源限流，并限制同时密码运算数。留言每条 280 字、每用户每天 20 条、全站每天 500 条、15 秒发送间隔。匿名仅隐藏对外署名，内部作者关联保留到当日清空。所有浏览器写接口验证同源，留言按纯文本渲染。

`data/accounts.json` 保存昵称、密码散列、会话散列与发送间隔时间；`data/board.json` 只保存当天留言。每日定时物理覆盖旧留言，访问及服务启动时补清，运行数据全部被 Git 忽略。此存储实现面向一个 Node 进程的小范围试用，不支持多个进程同时写文件。

入场提示在用户实际看到小院后停留五秒，接着收起文字、折成纸飞机、沿弧线飞进树洞。抵达时洞口短暂亮起；仅作为引导，不自动打开聊天或发送文字。飞走后完整露出小院，底部“纸条”按钮可重新查看。选猫或其他弹窗打开时、页面进入后台时暂停计时与飞行；系统减少动态效果时只在五秒后收起提示。中途改变窗口尺寸会重新展示纸条并计时，以便重新计算目的地。

小猫以有限速度逐步加速、靠近目标时减速；朝向由实际移动方向决定，脚步帧随路程推进。轻微鼠标抖动不会让站稳的小猫反复启动。拖动时抬起，松手时轻轻落回原位；停止移动后不保持空转的绘制循环。

## Agent 的明确范围

固定流程：用户来信 → 一次模型选择 → 最多三个本地只读工具 → 一次模型回信。无需工具时直接回信。没有自主反复规划、循环重试、子 Agent、任意网页抓取或执行代码工具。

- `search_reference_cards`：在本地短卡片中按中文双字片段和主题词评分，返回至多三条；没有命中即返回空。文化卡片须先开启生辰参考。
- `get_reflection_exercise`：读取关系沟通、检查想法、安排担忧时间中的一个可选练习。
- `get_birth_chart`：读取后端已经计算、用户本轮自愿提供的干支，不让模型自行排盘。

资料卡保持来源、章节、核查日期、证据类型。当前只有七张经人工筛选的短卡，是可运行的知识库起点，尚未做全文 RAG、语义嵌入或专业心理评估。模型可能归因不准，界面将链接标为“本次查阅”，而非权威认证。

## 后续阶段

- **小院互动**：点击花盆浇水、播种与简单生长状态，猫狗的少量闲置动画；先本地保存非敏感进度。
- **可玩的地图**：把整张背景拆成拥有明确许可的地块、建筑与精灵。需要移动、遮挡、碰撞时再引入 Phaser；复用已安装的官方素材、缩放和输入技能。
- **资料扩展**：按使用频率增加经核对的主题卡、做检索评估，再决定是否需要语义检索。古籍需分版本和章节，现代注本需另外确认授权。
- **准备上线**：确定公开范围、域名与部署方式后，再处理公网入口、访问控制、真实费用与压力测试。目前云端不参与开发。

聊天和花园可以分别迭代。不要用连续签到、聊天时长奖励或“只有 AI 理解你”的叙事驱动情绪依赖；花园允许用户什么也不做。

## 适配现有服务器

浏览器绘制背景、光效、猫咪与花瓣；服务器没有游戏帧循环。原生 Node HTTP 服务加一个历法依赖，本地 JSON 卡片检索，无数据库、向量服务或本地大模型。后台页面及信纸打开时暂停落瓣；系统减少动态效果设置生效。

场景 WebP 约 601 KiB，猫咪基础纹理约 30 KiB，动画图集约 114 KiB。以独占 3 Mbps 带宽估算，这三张素材传输下限约两秒，实际还受延迟、并发和缓存影响；不能承诺多人访问性能。静态图可缓存一天。默认同时最多三条模型请求、每个连接来源一条；一封回信最多两次模型 API 请求，所以每日次数不是精确费用预算。

2 核 2 GB 适合作为小规模试用的起点；本次只在本机验证，尚未进行云端并发负载测试，也没有把新版本部署到服务器。

室内背景额外约 342 KiB，四种表情图集约 165 KiB。进入小屋后背景才使用，小猫画布只在表情/毛色变化时重绘，摸猫动画由 CSS 执行；留言板仅在打开且页面可见时每 30 秒刷新，不在后台轮询。
